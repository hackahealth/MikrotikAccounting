# نرم‌افزار اکانتینگ و مدیریت مصرف کاربران میکروتیک

مدیریت کاربران **هات‌اسپات** و **VPN** میکروتیک با گزارش دقیق مصرف، زمان، سرعت، نوع استفاده و نوع دستگاه.
این برنامه خودش سرور RADIUS است؛ نیازی به FreeRADIUS یا User Manager نیست.

## امکانات

| بخش | توضیح |
|---|---|
| کاربران | تعریف کاربر محلی (تکی یا گروهی) + خواندن کاربران از **Active Directory ویندوز** (همگام‌سازی دستی یا خودکار هر ساعت، ساخت خودکار کاربر AD در اولین ورود، غیرفعال شدن خودکار کاربر حذف/غیرفعال‌شده در AD) |
| گروه‌ها | هر گروه: سرعت، سهمیه حجم (روزانه/هفتگی/ماهانه شمسی/کل)، ساعات مجاز، تعداد اتصال همزمان، حداکثر مدت اتصال، قطع در بیکاری، مجوز هات‌اسپات/VPN، Address-List. نگاشت گروه AD به گروه برنامه |
| محدودیت فردی | هر تنظیم گروه را می‌توان برای یک نفر جداگانه تغییر داد + تاریخ انقضا، IP ثابت، محدودیت MAC |
| سرعت | فرمت میکروتیک (`2M/8M` یا با Burst) به‌صورت `Mikrotik-Rate-Limit` به روتر ارسال می‌شود |
| حجم | باقی‌مانده سهمیه به‌صورت `Mikrotik-Total-Limit` ارسال می‌شود و برنامه هر ۳۰ ثانیه مصرف را چک می‌کند و در صورت اتمام، کاربر را قطع می‌کند |
| ساعات ورود | مثل `sat-wed 08:00-17:00; thu 08:00-13:00` (روزهای فارسی هم قبول است). خارج از ساعت، ورود رد می‌شود و `Session-Timeout` تا پایان بازه تنظیم می‌شود؛ در پایان بازه هم خودکار قطع می‌شود |
| احراز هویت | PAP، CHAP، MS-CHAPv2 (با کلیدهای MPPE برای VPN) — کاربران AD با PAP |
| گزارش مصرف | دانلود/آپلود، مدت آنلاین، تعداد اتصال، میانگین و حداکثر سرعت؛ نمودار روزانه و ساعتی؛ به تفکیک کاربر، گروه، سرویس؛ بازه شمسی دلخواه؛ خروجی Excel (CSV) |
| نوع استفاده | از Traffic-Flow میکروتیک: **استریم ویدیو** (یوتیوب، آپارات، فیلیمو، نماوا، نتفلیکس ...)، **دانلود فایل**، **وب‌گردی**، شبکه‌های اجتماعی، پیام‌رسان، تماس و ویدیوکنفرانس، موسیقی، به‌روزرسانی سیستم، فضای ابری، بازی، هوش مصنوعی، ایمیل، VPN/پروکسی، تورنت + جدول پربازدیدترین سایت‌ها برای هر کاربر و نمودار نوع استفاده در طول روز |
| نوع دستگاه | رایانه / موبایل / تبلت / تلویزیون + سیستم‌عامل، از روی: User-Agent مرورگر در صفحه لاگین هات‌اسپات، کلاس DHCP (`MSFT 5.0`، `android-dhcp`)، نام دستگاه (`DESKTOP-…`، `iPhone`، `Galaxy…`)، سازنده کارت شبکه (بانک ۳۱ هزار OUI داخل برنامه) و MAC تصادفی. قابل اصلاح دستی |
| آنلاین‌ها | لیست کاربران آنلاین با سرعت لحظه‌ای، دستگاه، مصرف و دکمه قطع |
| لاگ | همه ورودهای موفق و ناموفق با علت (رمز اشتباه، حجم تمام، خارج از ساعت ...) |
| صفحه کاربران اینترنت | آدرس `/my`: هر کاربر با همان نام کاربری و رمز اینترنت (محلی یا AD) وارد می‌شود، وضعیت حساب، حجم باقی‌مانده، مصرف روزانه (اینترنت / داخل شبکه)، نوع استفاده و اتصال‌های اخیرش را می‌بیند و رمزش را عوض می‌کند |
| کاربران پنل | نقش‌های مدیر سیستم، کارشناس IT، کارشناس منابع انسانی و **مدیر دفتر/واحد** + دسترسی سفارشی برای هر نفر، قفل بعد از ۵ رمز اشتباه، اجبار تغییر رمز پیش‌فرض، لاگ فعالیت پنل |
| دفتر و واحد | تعریف و ویرایش دفترها (یزد، تهران ...) و واحدها؛ هر کارمند یک دفتر و واحد دارد (دستی، گروهی یا خودکار از فیلدهای Office و Department در AD). مدیر هر دفتر/واحد فقط کارکنان خودش را **فقط مشاهده** می‌کند |
| گزارش مدیریتی | شاخص‌ها با مقایسه دوره قبل، روند روزانه، ساعت اوج، مصرف داخل/خارج ساعات کاری، سهم ترافیک تفریحی در ساعات کاری، تفکیک گروه/دفتر/واحد، پرمصرف‌ها؛ خروجی **Excel** با نمودار و نسخه چاپی/PDF |
| داخل شبکه / اینترنت | مصرف روزانه هر کاربر جدا به «اینترنت» و «داخل شبکه» (سرورها، دفاتر دیگر، VPN) در گزارش‌ها، داشبورد، گزارش مدیریتی، ساعات اتصال و Excel؛ برای هر روتر اینترفیس‌های WAN و/یا رنج IP داخلی تعیین می‌شود (با تشخیص خودکار از روتر) |
| ساعات اتصال کارکنان | اولین و آخرین اتصال روزانه، مدت آنلاین داخل و خارج از ساعات کاری، خروجی Excel (برای منابع انسانی) |
| اکانت محلی میکروتیک | ساخت، ویرایش، غیرفعال، حذف و صفر کردن مصرف **کاربران هات‌اسپات** و **اکانت‌های VPN (PPP Secret)** و پروفایل‌هایشان مستقیماً روی خود روتر؛ ساخت گروهی/کارت ووچر با چاپ؛ قطع اتصال |
| فولدر hotspot | بارگذاری ZIP صفحه ورود، نصب از راه دور روی یک یا چند روتر (FTP/SFTP)، پشتیبان خودکار قبل از نصب، بازگردانی، دانلود فولدر فعلی روتر، ویرایش فایل‌ها در پنل |

پنل کاملاً فارسی، راست‌به‌چپ و با تاریخ شمسی است و فونت/کتابخانه‌ها داخل برنامه هستند (بدون نیاز به اینترنت).

## نصب

پورت‌ها: `8080/tcp` پنل، `1812/udp` و `1813/udp` RADIUS، `2055/udp` Traffic-Flow. روتر باید به پورت `8728` (API)، `21` (FTP، برای فولدر hotspot) و `3799/udp` (قطع کاربر) خودش از سرور اجازه دسترسی بدهد (اسکریپت `mikrotik/setup.rsc` این‌ها را تنظیم می‌کند).

### ویندوز (Windows 10/11 یا Server 2012 به بعد)
1. فایل `mikrotik-accounting-windows.zip` را Extract کنید.
2. روی `install.bat` دوبار کلیک کنید و اجازه Administrator را بدهید.

همه چیز خودکار است و به نصب جداگانه Python یا اینترنت نیاز ندارد (Python و همه کتابخانه‌ها داخل بسته است):
برنامه در `C:\MikroTikAccounting` نصب می‌شود، فایل `.env` با کلید تصادفی ساخته می‌شود، پورت‌ها در فایروال ویندوز باز می‌شوند، به‌صورت سرویس پس‌زمینه (با شروع ویندوز، بدون نیاز به ورود کاربر و با راه‌اندازی مجدد خودکار در صورت خطا) ثبت و اجرا می‌شود و پنل در مرورگر باز می‌شود. یک میانبر هم روی دسکتاپ ساخته می‌شود.

- مدیریت سرویس: `C:\MikroTikAccounting\manage.bat` (وضعیت، شروع، توقف، راه‌اندازی مجدد، نمایش لاگ، بازیابی رمز کاربر پنل).
- به‌روزرسانی: بسته کوچک `mikrotik-accounting-update.zip` را Extract کنید و `update.bat` را اجرا کنید (یا نسخه کامل را Extract و دوباره `install.bat` را اجرا کنید). بسته آپدیت پوشه نصب را خودش پیدا می‌کند، سرویس را متوقف می‌کند، از دیتابیس و فایل‌های قبلی در `data\backups\update-<زمان>` پشتیبان می‌گیرد، فایل‌های جدید را جایگزین می‌کند و سرویس را دوباره اجرا می‌کند؛ دیتابیس، `.env` و Python دست نمی‌خورند و ستون‌ها/جدول‌های جدید خودکار اضافه می‌شوند. اگر نسخه جدید بالا نیاید، فایل‌های قبلی خودکار برگردانده می‌شوند. نسخه در پایین منوی پنل نوشته شده است.
- حذف: `uninstall.bat` (در مورد حذف داده‌ها سؤال می‌پرسد).
- اجرای آزمایشی بدون نصب سرویس: `run.bat`.
- اگر از بسته بدون Python (فقط سورس) استفاده کنید، `install.bat` / `run.bat` خودشان Python 3.12 و کتابخانه‌ها را دانلود و نصب می‌کنند (فقط داخل پوشه برنامه، بدون تغییر در سیستم).
- اگر نقش **NPS** ویندوز روی همین سرور فعال باشد، پورت 1812 را اشغال کرده است؛ نصب‌کننده هشدار می‌دهد. NPS را متوقف کنید یا پورت‌های RADIUS را در `.env` و روتر تغییر دهید.
- لاگ‌ها: `C:\MikroTikAccounting\data\logs`.

### Docker (لینوکس)
```bash
cp .env.example .env      # رمز پنل را عوض کنید
docker compose up -d --build
```
### لینوکس بدون Docker (Python 3.10+)
```bash
cp .env.example .env
./run.sh
```

سپس `http://IP-سرور:8080` را باز کنید. ورود اول: `admin` / `admin` (در اولین ورود باید رمز جدید انتخاب کنید).
حساب‌های `it` (کارشناس IT) و `hr` (منابع انسانی) هم ساخته می‌شوند ولی **غیرفعال**‌اند (رمز پیش‌فرض آن‌ها برای همه معلوم است)؛ مدیر از منوی «کاربران پنل» برایشان رمز می‌گذارد و فعالشان می‌کند. در نسخه‌های قبلی این دو حساب فعال ساخته می‌شدند؛ اگر هنوز رمز پیش‌فرض دارند، با به‌روزرسانی خودکار غیرفعال می‌شوند.
برای دیدن پنل با داده نمونه (بدون روتر): `DATA_DIR=./demo python -m scripts.demo_data` و بعد برنامه را با همان `DATA_DIR` اجرا کنید.

## راه‌اندازی قدم‌به‌قدم

1. **روترها**: روتر را با IP (همان `src-address` در تنظیم RADIUS روتر)، Secret و کاربر API اضافه کنید. دکمه «تست API» باید موفق باشد.
2. **تنظیم میکروتیک**: فایل `mikrotik/setup.rsc` را باز کنید، ۵ مقدار بالای آن را عوض کنید، با Winbox در Files آپلود کنید و در ترمینال بزنید: `/import file-name=setup.rsc`. این اسکریپت RADIUS هات‌اسپات و PPP، Interim-Update یک دقیقه‌ای، CoA، Traffic-Flow، اجبار DNS روتر و کاربر API محدود را تنظیم می‌کند.
3. **صفحه لاگین هات‌اسپات** (اختیاری، برای تشخیص دقیق‌تر دستگاه): در منوی «فولدر hotspot روترها» دکمه «پشتیبان / دانلود فولدر فعلی» را بزنید، همان پشتیبان را روی روتر نصب کنید؛ یا ZIP صفحه ورود خودتان را بارگذاری کنید. گزینه «افزودن خودکار کد تشخیص دستگاه» خط لازم را به `login.html` و `alogin.html` اضافه می‌کند.
4. **دفترها و واحدها**: در منوی «دفترها و واحدها» بسازید و کارکنان را تخصیص دهید (یا از AD خوانده می‌شود).
5. **گروه‌ها**: گروه‌ها را با سرعت، حجم و ساعات مجاز بسازید.
6. **کاربران**: کاربر محلی بسازید یا از منوی Active Directory همگام کنید.
7. **کاربران پنل**: برای هر مدیر دفتر/واحد یک کاربر با نقش «مدیر دفتر / واحد» بسازید و دفتر یا واحد او را تیک بزنید.

## کاربران پنل و سطوح دسترسی
| نقش | دسترسی پیش‌فرض |
|---|---|
| مدیر سیستم | همه چیز |
| کارشناس IT | کاربران و گروه‌ها، آنلاین‌ها و قطع اتصال، گزارش مصرف، دستگاه‌ها، لاگ ورود، همگام‌سازی AD، دفترها و واحدها، اکانت‌های محلی میکروتیک، فولدر hotspot |
| کارشناس منابع انسانی | فقط مشاهده: داشبورد، کاربران، گزارش مصرف، گزارش مدیریتی، ساعات اتصال کارکنان، خروجی Excel |
| مدیر دفتر / واحد | فقط مشاهده و فقط کارکنان دفتر/واحد خودش: داشبورد، کارکنان، آنلاین‌ها، گزارش مصرف، گزارش مدیریتی، ساعات اتصال، خروجی Excel |

محدوده مدیر: فقط دفتر = همه کارکنان آن دفتر؛ فقط واحد = آن واحد در همه دفترها؛ هر دو = آن واحد در همان دفتر. به کاربری که محدوده دارد هیچ دسترسی ویرایشی داده نمی‌شود.

**کاربران AD در پنل:** کاربر پنل می‌تواند حساب محلی (رمز همین پنل) یا **کاربر Active Directory** باشد که با نام کاربری و رمز دامنه وارد می‌شود (`sara.t`، `CORP\sara.t` یا `sara.t@corp.local`). ساده‌ترین راه: در صفحه ویرایش همان کاربر اینترنت (AD) دکمه «دادن دسترسی پنل» را بزنید؛ نقش «مدیر دفتر / واحد» و «دفتر خود این کاربر در AD» از پیش انتخاب شده است. مثلاً مدیر دفتر تهران با همان حساب AD خودش وارد می‌شود، فقط کارکنان دفتر تهران را می‌بیند، و اگر دفترش در AD عوض شود محدوده‌اش با همگام‌سازی بعدی (یا ورود بعدی) خودکار عوض می‌شود. همین شخص بدون ورود دوباره «مصرف اینترنت من» خودش را هم می‌بیند. رمز این حساب‌ها در AD عوض می‌شود، نه در پنل. مدیر سیستمی که هنگام نصب تعریف شده محلی می‌ماند و همیشه حداقل یک مدیر سیستم محلی فعال باید باشد تا اگر AD در دسترس نبود هم بتوان وارد شد.
**آموزش ورود اول:** هر کاربر پنل در اولین ورود (بعد از تغییر رمز اولیه) یک راهنمای مرحله‌ای می‌بیند که بخش‌های منو را یکی‌یکی روشن می‌کند و توضیح می‌دهد؛ فقط بخش‌هایی که آن نقش به آن‌ها دسترسی دارد (مثلاً مدیر دفتر فقط داشبورد، گزارش‌ها و کارکنان دفتر خودش را می‌بیند). کاربران اینترنت هم در اولین ورود به «مصرف اینترنت من» راهنمای همان صفحه را می‌بینند. آموزش یک بار خودکار نشان داده می‌شود (با «پایان» یا «رد شدن» دیگر خودکار نمی‌آید) و هر وقت خواستند از «راهنمای برنامه» در منو (یا دکمه «راهنما» در صفحه مصرف من) دوباره دیده می‌شود. مدیر با دکمه «نمایش دوباره آموزش برای همه» در صفحه کاربران پنل می‌تواند آن را برای همه دوباره فعال کند.
**یک صفحه ورود برای همه:** در `/login` کاربران پنل به پنل می‌روند و کاربران اینترنتی که دسترسی پنل ندارند با همان نام کاربری و رمز به صفحه مصرف خودشان (`/my`).
فراموشی رمز: `manage.bat` گزینه ۷، یا `python -m app.auth reset <user> <password>`.

## صفحه مصرف کاربران اینترنت (`/my`)
آدرس `http://SERVER:PORT/my` را به کاربران بدهید (یا لینک آن را در صفحه hotspot بگذارید؛ نمونه در `mikrotik/hotspot-login-snippet.html`). سرور در walled-garden هات‌اسپات است، پس کاربر قبل از ورود به اینترنت هم به آن دسترسی دارد.
- ورود با نام کاربری و رمز اینترنت: کاربران محلی با رمز ثبت‌شده در برنامه، کاربران AD با رمز ویندوز. اکانت‌هایی که فقط روی خود روتر تعریف شده‌اند رمزشان اینجا نیست و وارد نمی‌شوند.
- بعد از ۵ تلاش ناموفق، آن نام کاربری و آن IP ده دقیقه قفل می‌شوند.
- تغییر رمز کاربر محلی بلافاصله برای هات‌اسپات و VPN اعمال می‌شود. تغییر رمز کاربر AD در خود AD انجام می‌شود و فقط با **LDAPS** (یا StartTLS) ممکن است؛ سیاست رمز دامنه (طول، پیچیدگی، تکراری نبودن) رعایت می‌شود.
- این ورود هیچ دسترسی‌ای به پنل مدیریت نمی‌دهد. ورود و تغییر رمزها در «لاگ فعالیت پنل» ثبت می‌شود.

## اکانت‌های محلی میکروتیک
منوی «اکانت‌های محلی میکروتیک» از طریق API مستقیماً روی روتر کار می‌کند: کاربران و پروفایل‌های هات‌اسپات (`/ip hotspot user`) و اکانت‌ها و پروفایل‌های VPN (`/ppp secret`، `/ppp profile`).
سقف زمان، سقف حجم (مثل `5G`)، سرعت پروفایل، MAC و IP ثابت، فعال/غیرفعال، صفر کردن مصرف، قطع اتصال و ساخت گروهی (کارت ووچر با رمز تصادفی، قابل چاپ و CSV) پشتیبانی می‌شود.
روتر اکانت محلی را قبل از RADIUS بررسی می‌کند؛ مصرف این اکانت‌ها هم از Accounting در گزارش‌ها می‌آید و می‌توان برایشان دفتر و واحد تعیین کرد.

**کاربران بدون RADIUS Accounting:** برای اکانت‌های محلی هات‌اسپات/PPP (که روتر برایشان Accounting نمی‌فرستد) یا روتری که Accounting آن خاموش است، برنامه هر دقیقه لیست active روتر را با API می‌خواند و برای هر ورود یک اتصال می‌سازد: آنلاین بودن در داشبورد و «کاربران آنلاین» (با برچسب API)، حجم دانلود/آپلود (از `bytes-in/out` هات‌اسپات و شمارنده اینترفیس `<l2tp-...>` / `<pptp-...>` در VPN)، سرعت و مدت اتصال. اگر Accounting همان ورود از RADIUS برسد، اتصال API بسته می‌شود تا دوبار شمرده نشود. برای این کار کاربر API روتر لازم است (منوی روترها).

## دستگاه‌ها و سابقه IP / کاربر
منوی «دستگاه‌ها» برای هر MAC نشان می‌دهد الان (یا آخرین بار) چه IPی دارد، روی کدام روتر است و چه کاربری روی آن وارد شده؛ با کلیک روی MAC همه بازه‌ها دیده می‌شود: هر IP و هر کاربر با روتر، «از» و «تا» و مدت، و همه اتصال‌های آن دستگاه.
- منبع‌ها: لیست active و host هات‌اسپات، PPP (caller-id)، جدول ARP زنده، DHCP lease فعال و Accounting.
- هر ۶۰ ثانیه خوانده می‌شود؛ تا وقتی دستگاه پشت سر هم دیده شود همان بازه ادامه دارد و اگر بیش از ۱۵ دقیقه دیده نشود بازه بسته و دفعه بعد بازه تازه ثبت می‌شود (`DEVICE_HISTORY_GAP_MIN` در `.env`).
- دستگاه‌ها و سابقه‌شان **هرگز پاک نمی‌شوند**؛ دستگاهی که چند روز (پیش‌فرض ۳۰، قابل تغییر در همان صفحه) دیده نشود «راکد» نمایش داده می‌شود و با دیده شدن دوباره فعال می‌شود.
- جستجو در کل سابقه است: با IP معلوم می‌شود چه دستگاهی و چه زمانی آن را داشته، با نام کاربری دستگاه‌های کاربر؛ فیلد «در زمان» (مثل `1404/07/23 14:30`) نشان می‌دهد در آن لحظه چه دستگاه، IP و کاربری فعال بوده. در صفحه ویرایش هر کاربر هم دستگاه‌هایش آمده است.

## روترهای دفاتر دیگر (پشت NAT)
وقتی روتر دفترها از طریق اینترنت یا تونل و با NAT به سرور می‌رسند، همه بسته‌هایشان با IP مبدأ یکسان (IP روتر یا فایروال دفتر مرکزی) دیده می‌شود. برنامه هر بسته RADIUS را با این سه چیز به روتر درستش نسبت می‌دهد: **NAS-Identifier** (همان `/system identity` روتر)، **NAS-IP-Address** (IP خود روتر قبل از NAT) و **Secret** هر روتر (بسته با Secret روتری که آن را فرستاده امضا شده است). پس:
1. برای هر دفتر یک روتر جدا در منوی «روترها» تعریف کنید، با **IP خود همان روتر** (همان `src-address` در `/radius` آن روتر؛ نه IP روتر مرکزی) و ترجیحاً **Secret جدا**.
2. روی هر روتر یک identity یکتا بگذارید (`/system identity set name=Office-Tehran`) و همان را در فیلد NAS-Identifier وارد کنید (اگر API روتر تنظیم باشد، خودکار خوانده و پر می‌شود). در `mikrotik/setup.rsc` متغیر `routerName` همین کار را می‌کند.
3. در بخش «عیب‌یابی» صفحه روترها برای هر بسته رسیده، IP مبدأ، NAS-Identifier و NAS-IP-Address و روتری که تشخیص داده شده آمده است؛ روتری که تعریف نشده یا Secret آن نمی‌خورد با دکمه «افزودن این روتر» با همان مشخصات اضافه می‌شود.
4. **Traffic-Flow** دفاتر هم از همان IP مبدأ می‌رسد؛ برنامه هر Flow را به روتری نسبت می‌دهد که کاربرِ صاحب آن IP رویش آنلاین است (و رنج داخلی / WAN همان روتر را برای تفکیک داخل شبکه و اینترنت به کار می‌برد). اگر دفترها رنج IP یکسان به کاربران می‌دهند (مثلاً همه `192.168.88.0/24`)، برای روتر آن دفتر «پورت Traffic-Flow اختصاصی» (مثلاً 2056) بگذارید و در روتر `/ip traffic-flow target set [find] port=2056`؛ برنامه آن پورت را باز می‌کند و قانون فایروال ویندوز آن را خودش اضافه می‌کند (اگر NAT با Port-Forward است، آن پورت را هم Forward کنید).
5. قطع کاربر (CoA) به IP خود روتر فرستاده می‌شود؛ اگر سرور به IP روتر دفتر دسترسی مستقیم ندارد، API آن روتر را با «آدرس API» قابل دسترس تنظیم کنید تا قطع از راه API انجام شود.

## گراف ترافیک روترها
منوی «ترافیک روترها» برای هر روتر دو بخش جدا دارد: **اینترنت (WAN)** و **شبکه داخلی (LAN)**. در هر بخش سرعت لحظه‌ای (میانگین هر دقیقه) و حجم تجمعی روز رسم می‌شود؛ خط امروز پررنگ روی خط کمرنگ دیروز می‌افتد. با انتخاب روز، همان روز روی روز قبلش نمایش داده می‌شود. پیش‌فرض هر بخش جمع اینترفیس‌هایی است که در فرم روتر به‌عنوان WAN و «اینترفیس‌های شبکه داخلی» تیک خورده‌اند؛ از فهرست بالای هر بخش هر اینترفیس دیگر روتر را هم می‌توانید ببینید. داده از شمارنده‌های `/interface` که در همان خواندن دقیقه‌ای API گرفته می‌شود ساخته می‌شود (درخواست اضافه‌ای به روتر نمی‌رود). ریز دقیقه‌ای `IFACE_SAMPLE_DAYS` روز (پیش‌فرض ۱۴) و حجم روزانه به اندازه `SAMPLE_RETENTION_DAYS` نگه داشته می‌شود. دسترسی «گراف ترافیک روترها» به‌طور پیش‌فرض برای مدیر، IT و مدیر دفتر/واحد است؛ مدیر دفتر فقط روترهای دفتر خودش را می‌بیند.

ستون «بار مانیتورینگ روی لینک» در صفحه روترها تخمین حجمی است که این برنامه روزانه از لینک هر دفتر تا سرور مصرف می‌کند: خواندن API (هر دقیقه) و بسته‌های Traffic-Flow (اندازه‌گیری‌شده از زمان راه‌اندازی برنامه). باز کردن گراف‌ها و گزارش‌ها چیزی از روتر دفتر نمی‌خواند.

## نوع تجهیزات، ورود کاربران به رایانه‌ها و فهرست شبانه
- **نوع تجهیز:** در صفحه «دستگاه‌ها» نوع هر MAC را از فهرست انتخاب کنید (رایانه، لپ‌تاپ، تین کلاینت، سرور، پرینتر، اسکنر، تلفن VoIP، روتر، سوییچ، اکسس پوینت، دوربین، NVR، ذخیره‌ساز، حضور و غیاب، UPS، ...). با تیک چند دستگاه، نوع همه یکجا تعیین می‌شود. در صفحه هر دستگاه یک «نام / توضیح» هم می‌توان گذاشت (مثلاً «پرینتر طبقه دوم»). نوعی که دستی تعیین شود ثابت می‌ماند. پرینترها، تلفن‌ها، دوربین‌ها، تین کلاینت‌ها و روترهای رایج از روی نام میزبان (`NPI…`، `BRW…`، `SEP…`، `WYSE…`) یا سازنده کارت شبکه خودکار تشخیص داده می‌شوند.
- **آخرین کاربر واردشده روی هر رایانه** (پایین صفحه دستگاه‌ها):
  - روش ۱ (کنترلر دامنه): هر ۲ دقیقه رویدادهای 4768/4770 (Kerberos) از Security Log کنترلر دامنه با کاربر سرویس AD خوانده می‌شود. IP رایانه از رویداد، و MAC از سابقه IP روترها پیدا می‌شود. یک بار روی DC: کاربر سرویس را عضو گروه **Event Log Readers** کنید و `Enable-NetFirewallRule -DisplayGroup "Remote Event Log Management"` را اجرا کنید. این روش فقط وقتی برنامه روی ویندوز (عضو همان شبکه) نصب است کار می‌کند.
  - روش ۲ (اسکریپت ورود GPO): خطی که صفحه نشان می‌دهد در User Configuration › Windows Settings › Scripts › Logon گذاشته شود؛ هر رایانه هنگام ورود نام کاربر و نام رایانه را به برنامه می‌فرستد.
- **فهرست شبانه:** هر شب ساعت ۲۱:۰۰ (قابل تغییر) دستگاه‌هایی که روی شبکه‌اند ثبت می‌شوند، با دو ستون جدا: آخرین ورود ویندوز (AD) روی همان رایانه، و آخرین کاربر هات‌اسپات / VPN آن دستگاه (و این‌که سر ساعت هنوز وصل بود یا نه)؛ منوی «سیستم‌های روشن شبانه»، پیش‌فرض فقط رایانه‌ها (رایانه، لپ‌تاپ، تین کلاینت، سرور)، با فیلتر نوع و خروجی Excel. «روشن» یعنی دستگاه در آخرین خواندن روترها (ARP / DHCP / هات‌اسپات) دیده شده؛ پس روتر باید Gateway آن شبکه باشد و API آن تنظیم شده باشد.

## گزارش تماس‌های ایزابل
منوی «سرورهای ایزابل» (دسترسی IT/مدیر) برای افزودن یک یا چند سرور ایزابل است. برنامه سوابق تماس (CDR) را هر دقیقه از دیتابیس `asteriskcdrdb` هر سرور با یک کاربر **فقط‌خواندنی** MySQL می‌خواند و هیچ تغییری در ایزابل نمی‌دهد.
1. روی هر ایزابل (SSH): `mysql -u root -p` (رمز در `/etc/issabel.conf` با نام `mysqlrootpwd`) و
   `CREATE USER 'acct_reader'@'APP_IP' IDENTIFIED BY 'StrongPass'; GRANT SELECT ON asteriskcdrdb.* TO 'acct_reader'@'APP_IP'; FLUSH PRIVILEGES;` (`APP_IP` = IP سرور برنامه).
2. اگر MySQL فقط روی localhost گوش می‌دهد، `bind-address` را در `/etc/my.cnf` حذف یا به IP ایزابل تغییر دهید و سرویس mariadb/mysqld را ری‌استارت کنید.
3. پورت 3306 را فقط برای IP سرور برنامه باز کنید (فایروال ایزابل یا `iptables`).
4. در برنامه «افزودن سرور»: نام، IP، کاربر و رمز، **بازه داخلی‌های همان سرور** (مثلاً `100-399`) و در صورت نیاز نام ترانک‌ها و دفتر. «ذخیره و تست اتصال» تعداد تماس‌های موجود را نشان می‌دهد. «خواندن سوابق قبلی» تا یک سال گذشته را وارد می‌کند (تکراری‌ها دوباره ثبت نمی‌شوند).
- **دو یا چند سرور:** هر سرور جدا تعریف می‌شود و بازه داخلی خودش را دارد. تماس بین دو سرور خودتان (مثلاً از داخلی ۱۲۰ دفتر مرکزی به ۵۲۰ دفتر دیگر) «داخلی» حساب می‌شود، نه ورودی/خروجی.
- **داخلی هر نفر:** در فرم کاربر بخش «داخلی‌های تلفن»، یا از جدول «داخلی‌های بدون صاحب». هر تخصیص بازه تاریخ دارد؛ با تغییر داخلی، تماس‌های قبلی به نام صاحب قبلی می‌ماند. یک نفر می‌تواند چند داخلی داشته باشد. تخصیص می‌تواند برای یک سرور یا همه سرورها باشد.
- **گزارش «تماس‌ها»** (مدیر، HR، مدیر دفتر/واحد در محدوده خودش): تعداد ورودی/خروجی/داخلی، پاسخ‌داده و بی‌پاسخ، مدت مکالمه، میانگین زمان زنگ، نقشه ساعت×روز هفته، روند روزانه، پرتماس‌ترین مقصدها (موبایل/شهری/بین‌شهری/بین‌الملل) و تماس‌گیرنده‌ها، **تماس‌های از دست رفته‌ای که پاسخ داده نشده‌اند**، جدول هر نفر و هر دفتر/واحد، فیلتر سرور و جهت، و خروجی Excel. بخش تماس‌ها به گزارش مدیریتی و Excel مدیریتی هم اضافه شده است.
- زمان تماس‌ها همان ساعت ایزابل خوانده می‌شود؛ ساعت/منطقه زمانی ایزابل باید `Asia/Tehran` باشد.
- **صف‌ها (Queue):** از همان CDR و بدون تنظیم اضافه در ایزابل، برای هر صف این موارد محاسبه می‌شود: تعداد تماس، پاسخ توسط اپراتور، رهاشده، میانگین و بیشترین زمان انتظار، انتظار تا رها کردن، و سطح سرویس (درصد پاسخ در N ثانیهٔ اول؛ پیش‌فرض ۲۰ ثانیه، در «تنظیم گزارش تماس» صفحهٔ سرورهای ایزابل). Queue() خودش تماس را پاسخ می‌دهد، پس تماسی که اپراتور برنداشته «بی‌پاسخ» حساب می‌شود، نه پاسخ‌داده.
- **تماس‌های زنده (AMI، اختیاری):** در فرم سرور، کاربر و رمز AMI را وارد کنید. صفحهٔ «تماس‌های زنده» (دکمهٔ بالای «تماس‌ها») هر ۵ ثانیه نشان می‌دهد چه کسی در حال مکالمه، زنگ یا انتظار در صف است. روی ایزابل به انتهای `/etc/asterisk/manager_custom.conf` اضافه کنید و `asterisk -rx "manager reload"` را اجرا کنید (پورت 5038 را فقط برای IP سرور برنامه باز کنید):
  ```
  [acct_live]
  secret = StrongPass2
  deny = 0.0.0.0/0.0.0.0
  permit = APP_IP/255.255.255.255
  read = call,reporting
  write = reporting
  ```
- **پیشنهاد تخصیص از AD:** فیلد ipPhone کاربران در همگام‌سازی AD خوانده می‌شود. داخلی‌هایی که صاحب ندارند ولی در AD صاحب دارند در صفحهٔ سرورهای ایزابل با یک کلیک تخصیص داده می‌شوند.
- **هشدار تماس بی‌پاسخ:** اگر تعداد تماس‌های ورودی بی‌پاسخ در یک ساعت به حد تعیین‌شده برسد، حداکثر ساعتی یک بار در «هشدارها» اعلان می‌شود. پیش‌فرض این هشدار خاموش است.

## پایش شبکه، ورود ناموفق، قفل و مجوز موقت
- **پایش روترها و تانل‌ها** (منوی «پایش روترها و تانل‌ها»، فقط مدیر سیستم و کارشناس IT): هر بار خواندن API بررسی می‌کند که روتر در دسترس است و اینترفیس‌های تانل running هستند. همچنین از خود روتر به آدرس‌هایی که در فرم روتر («پایش») نوشته‌اید ping می‌گیرد، مثلاً سرور دفتر مرکزی از راه تانل. قطع یا کندی که دو بار پشت‌سرهم دیده شود ثبت و در «هشدارها» اعلان می‌شود. وصل شدن دوباره هم اعلان می‌شود. دسترس‌پذیری ۱ تا ۳۰ روز هر مورد قابل مشاهده است.
- **ورود ناموفق و قفل** (منوی «ورود ناموفق و قفل»): ورودهای ناموفق بر حسب کاربر و بر حسب مبدأ (MAC هات‌اسپات یا IP کلاینت VPN) نمایش داده می‌شود. هر کاربر، MAC یا IP را می‌توان دستی قفل کرد. پیش‌فرض اگر ۱۰ بار در ۲۴ ساعت رمز اشتباه وارد شود، کاربر و مبدأ خودکار قفل می‌شوند و هشدار برای مدیر سیستم و کارشناس IT ثبت می‌شود. قفل‌شده نه به هات‌اسپات وصل می‌شود نه VPN و اتصال فعالش هم قطع می‌شود.
- **مجوز موقت** (منوی «مجوزهای موقت» یا دکمهٔ «مجوز موقت» در فرم کاربر): کار خارج از ساعات مجاز یا اینترنت آزاد (بدون سقف حجم) برای یک بازهٔ تاریخ و ساعت ثبت می‌شود. نوشتن نام دستوردهنده الزامی است.
- **پیام ورود ویندوز**: در صفحهٔ دستگاه‌ها، بخش «پیام هنگام ورود به ویندوز»، متن اطلاعیه را بنویسید و فعال کنید. خط اسکریپت ورود (GPO) که همان‌جا نمایش داده می‌شود بعد از ورود، پنجرهٔ پیام را با اطلاعیه و وضعیت حجم کاربر نشان می‌دهد. اگر قبلاً اسکریپت ورود را گذاشته‌اید، خط جدید را جایگزین کنید.
- **هشدار ۸۰٪ حجم**: وقتی مصرف از حد هشدار (پیش‌فرض ۸۰٪، قابل تغییر در همان بخش) گذشت، در صفحهٔ «اینترنت من»، پیام ورود ویندوز و نوار بالای صفحهٔ هات‌اسپات (alogin.html / status.html) نمایش داده می‌شود. بروزرسانی فولدر hotspot از پنل کد آن را خودکار اضافه می‌کند. برای اضافه کردن دستی، `mikrotik/hotspot-login-snippet.html` را ببینید.
- **اینترنت دقیق از اینترفیس**: گزارش مدیریتی سه عدد جدا دارد که از شمارندهٔ اینترفیس‌های روتر خوانده می‌شوند و به کاربر یا هات‌اسپات وابسته نیستند: کل اینترنت واقعی (WAN)، تانل، و اینترنت منهای تانل. جدول به تفکیک هر روتر/دفتر هم در گزارش و خروجی Excel آمده است.

## گزارش دفاتر و سرورها/دستگاه‌های شبکه
- **سرورها و دستگاه‌های شبکه** (منوی «سرورها و دستگاه‌های شبکه»): سرورها (اتوماسیون، مالی، فایل و ...)، دوربین‌ها، NVR، تلفن‌ها و ایزابل را برای هر دفتر/روتر یا «همه دفاتر» با IP، رنج یا CIDR تعریف کنید. برای هر کدام مشخص می‌شود از اینترنت و از دفاتر دیگر (تانل) قابل دسترس است یا نه.
- **گزارش دفاتر** (منوی «گزارش دفاتر» یا کلیک روی نام روتر در گزارش مدیریتی): مستقل از کاربر هات‌اسپات. اینترنت واقعی، تانل و اینترنت منهای تانل از اینترفیس روتر؛ ترافیک هر دستگاه (MAC، IP، کاربر ویندوز، کاربر هات‌اسپات) به تفکیک اینترنت، تانل، شبکه داخلی و سرورهای تعریف‌شده؛ و ترافیک سرورها، دوربین‌ها و تلفن‌ها جدا. ترافیک اینترنتی دستگاهی که «از اینترنت قابل دسترس» نیست با نشان نارنجی مشخص می‌شود. خروجی Excel دارد.
- این گزارش از NetFlow روتر ساخته می‌شود، پس فقط ترافیکی که از روتر عبور می‌کند دیده می‌شود. ترافیک دو دستگاه در یک سابنت که مستقیم از سوییچ رد می‌شود در آن نیست.

## نگهداری سابقه و نسخهٔ روترها
- **نگهداری سابقه** (منوی «نگهداری سابقه»، فقط مدیر سیستم): سابقهٔ مصرف کاربران و ترافیک روزانهٔ روترها پیش‌فرض ۶ ماه نگه داشته می‌شود و قدیمی‌ترش هر شب حذف می‌شود. مدت قابل تغییر است و عدد ۰ یعنی هیچ‌وقت حذف نشود. حجم پایگاه داده، تعداد ردیف‌ها و قدیمی‌ترین تاریخ هر نوع داده نمایش داده می‌شود. هر نوع داده (مصرف، ترافیک روترها، لاگ‌ها، سابقهٔ دستگاه‌ها، تماس‌ها، لاگ پنل) را می‌توان دستی از یک تاریخ به قبل حذف کرد. بعد از حذف، فضای آزادشده به دیسک برمی‌گردد. سابقهٔ کاربرانی که سقف حجمشان «کل» است حذف نمی‌شود.
- در گزارش‌ها بازهٔ «۶ ماه اخیر» اضافه شده و صفحهٔ «اینترنت من» جدول مصرف ۶ ماه اخیر را نشان می‌دهد.
- **نسخه و بروزرسانی روترها** (منوی «نسخه و بروزرسانی روترها»، مدیر سیستم و کارشناس IT): نسخهٔ RouterOS، مدل، معماری، فریمور، uptime، CPU، حافظه، دیسک و بسته‌های هر روتر نمایش داده می‌شود. روی روترهای انتخاب‌شده می‌توان این کارها را کرد: بررسی نسخهٔ جدید (با انتخاب کانال)، دانلود و نصب از سرور میکروتیک، ارتقای فریمور RouterBOARD و ریبوت.
- **ارسال فایل بروزرسانی**: اگر روتر به سرور میکروتیک دسترسی ندارد، فایل .npk را در همین صفحه بارگذاری کنید و برای روترها بفرستید. فایل با FTP/SFTP فرم روتر به ریشهٔ فایل‌های روتر کپی می‌شود و با ریبوت (گزینهٔ «بعد از ارسال ریبوت شود») نصب می‌شود. معماری فایل (arm64، mipsbe و ...) با روتر مقایسه می‌شود و اگر یکی نباشد ارسال نمی‌شود. همهٔ عملیات در «لاگ فعالیت پنل» ثبت می‌شود.

## کنترل دسترسی، آدرس‌های حساس، بررسی اینترنت و آنلاین‌ها، امکانات ویندوز
- **بررسی اینترنت روترها:** در گزارش مدیریتی، حجم هر اینترفیس WAN جدا نشان داده می‌شود. اینترفیسی که فقط زیربنای یک PPPoE/VLAN انتخاب‌شده است (مثل ether1 زیر Pishgaman) یا آدرس شبکهٔ داخلی دارد یا عضو بریج LAN است، خط می‌خورد و در «کل اینترنت» حساب نمی‌شود. اینترفیسی که ارسالش خیلی بیشتر از دریافت است هشدار می‌گیرد. مسیر پیش‌فرض واقعی روتر هم نمایش داده می‌شود تا فرم روتر اصلاح شود.
- **تأیید آنلاین‌ها با پینگ:** روتر هر ۵ دقیقه (قابل تغییر در صفحهٔ دستگاه‌ها) همهٔ دستگاه‌های آنلاین را با ARP-ping و پینگ عادی آزمایش می‌کند. ARP-ping با فایروال ویندوز هم جواب می‌دهد. دستگاهی که جواب ندهد دیگر از روی ARP ثابت یا host قدیمی هات‌اسپات آنلاین حساب نمی‌شود. در «کاربران آنلاین» اتصالی که دستگاهش جواب نمی‌دهد علامت می‌خورد و می‌توان آن را خودکار قطع کرد.
- **کنترل دسترسی** (منوی «کنترل دسترسی و سایت‌ها»، مدیر سیستم و کارشناس IT): فهرست سایت‌های مسدود (یا حالت سخت‌گیرانه با فهرست مجاز) و صفحهٔ «دسترسی مسدود است» برای http. استثناها (MAC/IP و نوع‌هایی مثل تلفن IP) بدون ورود هات‌اسپات و بدون محدودیت کار می‌کنند. با روشن کردن محدودیت داخلی، کاربر بعد از ورود فقط به مقاصد مجاز داخلی دسترسی دارد. مجوز موقت «اینترنت آزاد» از مسدودی معاف می‌کند. قوانین فقط روی روترهایی که فعال کنید و با توضیح macc نوشته می‌شوند. پیش از فعال‌سازی، پیش‌نمایش دستورات را ببینید. «غیرفعال» همهٔ آن‌ها را برمی‌دارد.
- **آدرس‌های حساس:** در «سرورها و دستگاه‌های شبکه» یک مورد را «حساس» کنید (مثلاً NVR) و مبدأهای مجاز را بنویسید. دسترسی از جای دیگر هم از NetFlow و هم از قانون روتر الارم می‌دهد، و در حالت «مسدود + الارم» بسته هم می‌شود.
- **ورود کاربران ویندوز:** چه کسی، کی و روی کدام رایانه/IP/دفتر وارد شده است.
- **پیام به رایانه‌ها:** پیام فوری با msg.exe به یک کاربر، یک دفتر یا همهٔ رایانه‌های روشن. یک بار با GPO مقدار AllowRemoteRPC=1 و SMB از سرور برنامه باز شود.

## عیب‌یابی دریافت اطلاعات
پایین جدول «روترها» نشان داده می‌شود از هر IP چه بسته‌هایی رسیده: درخواست ورود، Accounting، بسته‌های دور ریخته شده (IP ناشناس)، Secret اشتباه، و از هر فرستنده Traffic-Flow تعداد Flowها و این‌که چندتا به کاربر آنلاینی خورده‌اند، همراه با راهنمای رفع مشکل. ستون «آنلاین (RADIUS / API)» تعداد اتصال‌های هر روتر را از هر روش نشان می‌دهد.

## بروزرسانی فولدر hotspot از راه دور
منوی «فولدر hotspot روترها»:
1. ZIP فولدر hotspot را بارگذاری کنید (اگر فایل‌ها داخل پوشه `hotspot` باشند، خودکار تشخیص داده می‌شود).
2. بسته و روترها را انتخاب و «نصب» بزنید. مسیر فولدر (مثلاً `hotspot` یا `flash/hotspot`) از پروفایل هات‌اسپات روتر خوانده می‌شود.
3. قبل از نصب از فولدر فعلی هر روتر پشتیبان گرفته می‌شود؛ برای بازگشت، همان پشتیبان را نصب کنید.

انتقال با FTP (پیش‌فرض) یا SFTP و با همان کاربر API روتر انجام می‌شود. فایل‌های متنی بسته (`login.html` و ...) را می‌توانید در همان پنل ویرایش کنید.

## اتصال به Active Directory
در منوی **Active Directory**: آدرس DC، دامنه (مثل `corp.local`)، یک کاربر سرویس (فقط‌خواندنی کافی است، مگر بخواهید تغییرات را در AD هم ثبت کنید؛ پایین‌تر)، Base DN و در صورت نیاز فیلتر (مثلاً فقط اعضای گروه `Internet-Users`). سپس «تست اتصال» و «همگام‌سازی».
- **Base DN** مسیری از AD است که کاربران و گروه‌ها در آن جستجو می‌شوند. اگر خالی بماند، برنامه خودش ریشه دامنه را از DC می‌خواند (برای `corp.local` می‌شود `DC=corp,DC=local`). برای محدود کردن به یک OU مثلاً `OU=Staff,DC=corp,DC=local` بنویسید.
- «تست اتصال» علاوه بر ورود کاربر سرویس، Base DN استفاده‌شده و تعداد کاربرانی را که پیدا می‌شوند نشان می‌دهد.
- اگر همگام‌سازی هیچ کاربری پیدا نکند، کاربران AD فعلی غیرفعال نمی‌شوند.
- رمز کاربران AD در برنامه ذخیره نمی‌شود و هر بار مستقیماً با AD بررسی می‌شود؛ بنابراین روش احراز هویت این کاربران باید **PAP** باشد:
  - هات‌اسپات: `http-pap` (اسکریپت فعالش می‌کند؛ بهتر است صفحه لاگین HTTPS باشد).
  - VPN: SSTP یا OpenVPN یا L2TP/IPsec با `authentication=pap` (تونل خودش رمز شده است). PPTP با PAP امن نیست.
- کاربران محلی با همه روش‌ها (از جمله MS-CHAPv2 ویندوز/اندروید/آیفون) کار می‌کنند.
- برای اعمال تنظیمات مختلف به گروه‌های AD، DN گروه AD را در فرم گروه وارد کنید. «نمایش گروه‌های AD» لیست DNها را نشان می‌دهد.
- LDAPS (پورت 636) توصیه می‌شود.
- از AD این‌ها خوانده می‌شود: نام، ایمیل، تلفن، **موبایل** (`mobile`)، سمت (`title`)، شرکت (`company`)، محل/شهر (`l`)، دفتر (`physicalDeliveryOfficeName`)، واحد (`department`)، کد پرسنلی (`employeeID`) و عضویت گروه‌ها.

### ویرایش کاربران AD و ثبت تغییرات در AD
- در فرم ویرایش کاربر AD، تغییر نام، ایمیل، موبایل، تلفن، سمت، شرکت، محل، دفتر، واحد، کد پرسنلی و گروه (با تیک «در Active Directory هم ثبت شود») مستقیماً در AD نوشته می‌شود. اگر AD نپذیرد، هیچ تغییری ذخیره نمی‌شود و علت نمایش داده می‌شود.
- **ویرایش گروهی:** در صفحه کاربران چند کاربر را تیک بزنید (یا با تیک سرستون همه کاربران فیلتر شده را)؛ کادر «ویرایش گروهی» باز می‌شود. گروه، دفتر، واحد، محل، سمت، شرکت، تلفن، موبایل و محدودیت‌های اینترنت (سرعت، سهمیه، ساعات، اتصال همزمان، انقضا) را می‌توان یکجا عوض کرد؛ فقط فیلدهای تیک‌خورده تغییر می‌کنند. نتیجه هر کاربر جدا نمایش داده می‌شود.
- تغییر گروه در AD: کاربر به گروه AD که به گروه جدید نگاشت شده (DN گروه در فرم گروه) اضافه و از گروه‌های AD نگاشت‌شده دیگر خارج می‌شود تا همگام‌سازی بعدی همان گروه را نگه دارد.
- **اجازه نوشتن:** کاربر سرویس باید روی OU کاربران اجازه نوشتن این خصیصه‌ها و روی گروه‌های نگاشت‌شده اجازه نوشتن `member` را داشته باشد. در «Active Directory Users and Computers» روی OU کاربران راست‌کلیک > Delegate Control > کاربر سرویس > Create a custom task > Only the following objects: User objects > Property-specific: Write برای `displayName, mail, telephoneNumber, mobile, title, company, l, physicalDeliveryOfficeName, department, employeeID`؛ و روی OU گروه‌ها: Group objects > Write `member` (یا گزینه آماده «Modify the membership of a group»). بدون این اجازه پیام «Delegate Control» نمایش داده می‌شود و فقط کاربرانی که اجازه دارند تغییر می‌کنند.

### مدیریت Active Directory از سامانه (فقط از آدرس داخلی)
منوی **مدیریت Active Directory** (`/adm`) برای مدیر ارشد و کسانی که در «کاربران پنل» دسترسی «مدیریت Active Directory» را به آن‌ها بدهید:
- **کاربران:** جستجو، ساخت کاربر جدید در OU دلخواه (نام کاربری، نام، رمز اولیه، «تغییر رمز در اولین ورود»، مشخصات و گروه‌ها)، ویرایش مشخصات، فعال/غیرفعال، باز کردن قفل، تعیین رمز، انتقال به OU دیگر، عضویت در یک یا چند گروه و حذف (با نوشتن نام کاربری برای تأیید).
- **گروه‌ها:** ساخت گروه امنیتی یا توزیع (Global / Domain Local / Universal)، افزودن و خارج کردن اعضا (کاربر یا گروه)، توضیح، حذف.
- **OUها:** درخت OUها، ساخت و حذف OU خالی. **رایانه‌ها:** فهرست، فعال/غیرفعال و انتقال به OU.
- **فقط از آدرس داخلی:** این منو و همهٔ مسیرهای `/adm` فقط وقتی سامانه از داخل شبکه و با آدرس داخلی (مثل `http://192.168.1.5:9090`) باز شود وجود دارند. با IP پابلیک یا از بیرون شبکه حتی با حساب مدیر، صفحه «یافت نشد» است. نام دامنهٔ عمومی سامانه را در صفحهٔ Active Directory در «آدرس‌های عمومی سامانه» بنویسید. شبکه‌های داخلی همان «شبکه‌های داخلی» صفحهٔ تفکیک مصرف است.
- **اجازه در AD:** حساب سرویس باید روی OUهای مورد نظر اجازهٔ ساخت/حذف/ویرایش کاربر و گروه داشته باشد (Delegate Control > «Create, delete, and manage user accounts»، «Reset user passwords»، «Create, delete and manage groups»، «Modify the membership of a group») یا عضو Account Operators باشد. **تعیین رمز فقط روی LDAPS (پورت 636) یا StartTLS** ممکن است؛ بدون آن کاربر غیرفعال و بدون رمز ساخته می‌شود.
- همهٔ تغییرات در «گزارش فعالیت‌ها» ثبت و کاربر تغییرکرده فوراً با سامانه همگام می‌شود.

### مقادیر انتخابی و تغییر گروهی خصیصه‌ها
- در زبانهٔ **«مقادیر انتخابی و تغییر گروهی»**، فهرست مقادیر سمت، واحد، دفتر، شهر و شرکت تعریف می‌شود. این مقادیر در فرم ساخت و ویرایش کاربر AD به‌صورت فهرست انتخابی می‌آیند و دیگر تایپی نیستند. نام دفترها، واحدها و شهرهای «دفترها و واحدها» هم خودکار در این فهرست هستند.
- **داخلی (ipPhone):** فقط داخلی‌های ایزابل قابل انتخاب‌اند که در تماس‌ها دیده شده‌اند، به کسی تخصیص داده نشده‌اند و در AD هم برای کاربر فعالی ثبت نیستند.
- برای هر خصیصه، همهٔ مقادیری که الان کاربران AD دارند با تعداد کاربر نمایش داده می‌شود. با «+ فهرست» آن مقدار به فهرست انتخابی اضافه می‌شود و با «تغییر برای همه» برای همهٔ آن کاربران یکجا عوض می‌شود.
- در فهرست کاربران می‌توان چند کاربر را تیک زد و یکجا این کارها را انجام داد:
  - تعیین یک خصیصه
  - افزودن به گروه یا خارج کردن از گروه
  - انتقال به OU دیگر
  - فعال یا غیرفعال کردن

### اتصال گروه‌های اینترنت به گروه، OU یا دفتر AD
در فرم گروه (منوی گروه‌ها) می‌توانید چند **گروه AD**، چند **OU** (همهٔ کاربران زیر آن) و چند **دفتر** (مقدار Office در AD یا نام دفتر در سامانه) بدهید. اگر کاربری با چند گروه جور شود، گروهی که **اولویت** کمتری دارد اعمال می‌شود. همگام‌سازی بعدی گروه کاربران را بر همین اساس تعیین می‌کند. اولین گروه AD همان است که با تغییر گروه کاربر در سامانه، کاربر به آن در AD اضافه می‌شود.

## مدیریت ایزابل از سامانه (API ایزابل، فقط از آدرس داخلی)
منوی **مدیریت ایزابل** (`/isx`) برای مدیر ارشد و کسانی که دسترسی «مدیریت ایزابل» دارند. این منو هم مثل مدیریت AD فقط از آدرس داخلی سامانه وجود دارد.
- همهٔ بخش‌هایی که API ایزابل دارد اینجا هست: داخلی‌ها، صف‌ها، گروه‌های زنگ، ترانک‌ها، مسیرهای ورودی و خروجی، IVR، شرط‌ها و گروه‌های زمانی، کنفرانس، اعلان‌ها، صداها، روز/شب، کدهای ویژه، پیجینگ، پارک، لیست سیاه، موزیک انتظار، DISA و غیره. فهرست بخش‌ها از خود ایزابل خوانده می‌شود.
- برای هر مورد می‌توانید فهرست، ویرایش همهٔ فیلدها، ساخت و حذف را انجام دهید. مقصدها از فهرست انتخاب می‌شوند و ایزابل بعد از هر تغییر تنظیمات را خودش اعمال می‌کند.
- **ساخت کاربر AD با داخلی:** در فرم «کاربر جدید در AD» می‌توانید سرور ایزابل و یک شمارهٔ آزاد را انتخاب کنید. داخلی با نام کاربر و رمز SIP تصادفی ساخته، در ipPhone کاربر AD ثبت و به کاربر تخصیص داده می‌شود. رمز SIP یک بار نمایش داده می‌شود.
- **تنظیم:** در «سرورهای ایزابل»، بخش «مدیریت ایزابل از سامانه»، کاربر و رمز ادمین وب ایزابل را وارد کنید. سپس «دریافت گواهی» را بزنید و اثر انگشت نمایش‌داده‌شده را با خروجی این دستور روی ایزابل مقایسه کنید: `openssl x509 -in /etc/pki/tls/certs/localhost.crt -noout -fingerprint -sha256`. اگر یکی بود، ثبت کنید. از آن به بعد فقط همان گواهی پذیرفته می‌شود.

## تفکیک مصرف داخل شبکه و اینترنت
در صفحه **روترها** برای هر روتر «ویرایش» را بزنید و در بخش «تفکیک مصرف داخل شبکه و اینترنت»:
1. **اینترفیس‌های اینترنت (WAN)** را تیک بزنید (مثل `ether1`، `pppoe-out1`) یا دکمه «تشخیص خودکار» را بزنید تا از Route پیش‌فرض، DHCP Client و PPPoE روتر پیدا شود. ترافیکی که از این اینترفیس‌ها رد شود «اینترنت» و بقیه «داخل شبکه» است.
2. و/یا **رنج IP داخلی** پشت آن روتر را بنویسید (هر خط یک CIDR، IP یا بازه `a-b`). مقصدهای این رنج‌ها همیشه «داخل شبکه»اند، حتی IP عمومی سرورهای خودتان.
3. پایین صفحه، **رنج‌های داخلی عمومی** (پیش‌فرض `10/8`، `172.16/12`، `192.168/16`) برای روترهایی است که WAN ندارند، و **استثنا: همیشه اینترنت** برای IP پروکسی/فایروالی که اینترنت از آن رد می‌شود.

4. **تانل به دفاتر دیگر:** ترافیک به شبکه دفاتر دیگر از راه تانل (روی بستر اینترنت) جدا با عنوان «تانل» ثبت می‌شود. پیش‌فرض همه اینترفیس‌های تانل روتر (EoIP، GRE، IPIP، L2TP، SSTP، PPTP، OVPN، WireGuard) خودکار تانل‌اند؛ می‌توانید فقط بعضی را تیک بزنید. برای IPsec بدون اینترفیس، رنج شبکه دفاتر دیگر را بنویسید. مقصد عمومی (اینترنت) که از تانل رد شود «اینترنت» می‌ماند.

ترتیب تصمیم برای هر جریان: استثنا ← رنج دفاتر دیگر (تانل) ← اینترفیس تانل ← رنج داخلی همان روتر ← اینترفیس WAN ← رنج‌های داخلی عمومی ← اینترنت.

**حجم بسته فقط از اینترنت کم می‌شود** (تیک «مصرف داخل شبکه و تانل از حجم بسته کاربران کم نشود» در پایین صفحه روترها، پیش‌فرض روشن): دسترسی به شبکه داخلی و تانل همچنان فقط بعد از ورود به هات‌اسپات است (بدون Walled Garden). در این حالت `Mikrotik-Total-Limit` به روتر فرستاده نمی‌شود (روتر همه ترافیک را می‌شمارد) و برنامه کاربری را که حجم اینترنتش تمام شود حداکثر حدود یک دقیقه بعد قطع می‌کند. محدودیت سرعت گروه روی همه ترافیک کاربر (از جمله تانل) اعمال می‌شود.
حجم کل هر کاربر از Accounting روتر است و حجم «داخل شبکه» از Traffic-Flow (دسته «شبکه داخلی») از آن کم می‌شود؛ پس Traffic-Flow روتر باید روی همه اینترفیس‌ها فعال باشد (`interfaces=all`، در `mikrotik/setup.rsc`). بدون Traffic-Flow همه مصرف «اینترنت» حساب می‌شود.
خروجی: ستون‌های اینترنت/داخل شبکه در گزارش کاربران، نمودار و جدول روزانه، «خروجی مصرف روزانه کاربران» (هر کاربر هر روز)، شیت «مصرف روزانه کاربران» در Excel مدیریتی و ستون‌های ساعات اتصال کارکنان.

## گزارش نوع استفاده چطور کار می‌کند و چقدر دقیق است
- روتر برای هر جریان ترافیک (flow) رکورد IPFIX می‌فرستد. برنامه IP کاربر را از جلسات RADIUS پیدا می‌کند، مقصد را با **DNS cache روتر** به نام سایت تبدیل می‌کند (به همین دلیل DNS کاربران به روتر هدایت می‌شود) و با قواعد دامنه، رنج IP سرویس‌های بزرگ (تلگرام، متا، نتفلیکس، گوگل، زوم/تیمز)، پورت و رفتار ترافیک دسته‌بندی می‌کند. مثلاً یک جریان بزرگ تکی روی سایت معمولی «دانلود فایل» حساب می‌شود و ترافیک سنگین QUIC گوگل «استریم ویدیو».
- محتوای HTTPS دیده نمی‌شود؛ تشخیص بر اساس مقصد است، پس دقت برای سرویس‌های شناخته‌شده بالا و برای سایت‌های ناشناخته در حد «وب‌گردی/سایر» است. قواعد در `app/classifier.py` قابل افزودن است.
- کاربرانی که DNS رمزشده (DoH) یا VPN شخصی دارند بیشتر با رنج IP و پورت دسته‌بندی می‌شوند.
- برای VPN معمولاً MAC کاربر به روتر نمی‌رسد، پس نوع دستگاه کاربران VPN اغلب «نامشخص» است.

## نکات
- مصرف و سرعت از Accounting روتر (هر یک دقیقه) ثبت می‌شود؛ گزارش ساعتی و سهمیه از همین داده است. سرعت لحظه‌ای از صف‌های داینامیک روتر (هر ۶۰ ثانیه) خوانده می‌شود.
- هات‌اسپات سهمیه را خودش هم با `Mikrotik-Total-Limit` اعمال می‌کند؛ برای VPN، برنامه کاربر را حداکثر حدود یک دقیقه بعد از اتمام حجم قطع می‌کند.
- قطع کاربر ابتدا با RADIUS Disconnect و در صورت شکست با API روتر انجام می‌شود.
- پایگاه داده پیش‌فرض SQLite در پوشه `data` است (برای چند صد کاربر کافی است). برای حجم بالا `DATABASE_URL` را روی PostgreSQL بگذارید.
- از پوشه `data` (و فایل `.env`) نسخه پشتیبان بگیرید. `SECRET_KEY` (یا فایل `data/secret.key` اگر در `.env` نباشد) را بعد از شروع تغییر ندهید؛ رمزهای ذخیره‌شده با آن رمز شده‌اند.
- منطقه زمانی پیش‌فرض `Asia/Tehran`، شروع هفته شنبه و ماه سهمیه، ماه شمسی است.

- رفع اشکال: نام کاربری/نام دستگاه عددی (مثل `1001`) در روتر، توضیح فارسی در اکانت‌های محلی روتر (UTF-8)، از کار افتادن RADIUS در ویندوز بعد از ریبوت روتر، تمام شدن اتصال‌های دیتابیس زیر بار، `_` و `%` در نام کاربری، ورود کاربر AD خارج از فیلتر، حساب‌های پیش‌فرض it/hr، ارسال CoA به 0.0.0.0، به ارث رسیدن مصرف کاربر حذف‌شده، API-SSL بدون گواهی روتر، پورت‌های فایروال از `.env`، خطای 500 در تاریخ/IP تکراری.

## ساختار پروژه
```
app/main.py           شروع برنامه (پنل + RADIUS + NetFlow + زمان‌بند)
app/radius_server.py  سرور RADIUS (احراز هویت و Accounting)
app/chap.py           CHAP / MS-CHAPv2 / کلیدهای MPPE
app/policy.py         سرعت، حجم، ساعات مجاز، اتصال همزمان
app/ldap_ad.py        Active Directory
app/netflow.py        دریافت NetFlow v5/v9/IPFIX
app/netscope.py       تفکیک ترافیک داخل شبکه / اینترنت (WAN و رنج‌های داخلی)
app/classifier.py     دسته‌بندی نوع استفاده (قابل ویرایش)
app/devices.py        تشخیص نوع دستگاه و سابقه IP / کاربر هر MAC
app/apisessions.py    اتصال‌های بدون RADIUS Accounting از لیست active روتر
app/udp.py            سوکت‌های UDP (RADIUS / Traffic-Flow) مقاوم در ویندوز
app/version.py        شماره نسخه
app/routeros.py       API میکروتیک، Disconnect و اکانت‌های محلی روتر
app/hotspot.py        بروزرسانی فولدر hotspot (FTP/SFTP، پشتیبان، بازگشت)
app/auth.py           کاربران پنل، نقش‌ها و دسترسی‌ها
app/scope.py          محدوده دفتر/واحد مدیران
app/mgmt.py           گزارش مدیریتی و ساعات اتصال کارکنان
app/xlsx.py           خروجی Excel
app/supervisor.py     اجرای دائمی به‌صورت سرویس (ویندوز)
app/jobs.py           قطع خودکار، خواندن اطلاعات روتر، همگام‌سازی AD
app/reports.py        گزارش‌ها
app/web.py            پنل وب
mikrotik/setup.rsc    اسکریپت تنظیم روتر
windows/              نصب‌کننده ویندوز (install / update / manage / uninstall)
scripts/build_windows.sh  ساخت بسته ویندوز همراه Python
tests/                تست‌ها:  python -m pytest tests
```
